# 问题4-2决策导向电价候选 Cheap PoC 协议

日期：2026-09-12。用户的模型修改授权见 `memory/decisions/D-017-q4-candidate-search-modified.md`。D-015批准的双层目标与回退保持不变，本协议在看到本轮结果前冻结。

## 1. 失败定位与新假设

前两轮表明：价格MAE显著下降不能保证费用下降；当前库存价值控制在oracle价格下仍失败；完美价格＋原贪心相对 `mean7` 的84天费用空间只有约0.56%。当前计划LP主要响应日内价格相对关系，而固定电价曲线在部分季节又优于近期历史均值。

新假设是：固定曲线提供稳定日内形状，14日均值提供近期价格状态，两者做收缩组合可以降低单一路线的季节失配；再用过去已结算日期的真实调度费用选择组合权重，可能比按MAE选择更贴近题目目标。

## 2. Structural Screen

### Baselines

- `fixed`：附件1价格曲线制定计划，附件4实际价格结算；结构 `KEEP`。
- `mean7`、`mean14`：此前已通过算法与信息审计的因果价格基线；结构 `KEEP`。

### Candidate A：静态收缩组合

定义

\[
\hat p_{d,t}^{(\alpha)}=(1-\alpha)p_t^{\mathrm{fixed}}+\alpha\bar p_{d,t}^{(14)},
\qquad \alpha\in\{0,0.25,0.5,0.75,1\}.
\]

只在开发期按库存调整费用选择一个 \(\alpha\)，随后在验证期和评估期冻结。该方法只增加一个有界权重，结构 `KEEP`。

### Candidate B：28日滚动费用选择器

每天0点，对上述五个权重分别统计此前28个已结束日的反事实调度费用。每个历史日都使用该日当时可获得的价格和供需历史、五个候选共同的已知日初SOC，并用统一库存调整消除日末SOC差异；选择累计费用最低的权重用于当天计划。完全相同时优先较小权重。它直接学习“哪种价格形状产生较低费用”，但反事实排序可能受28日窗口和历史状态代理影响，结构 `RISK`，必须用跨季节验证和MAE选择对照检验。

### Controls

- `rolling_mae_selector`：也在过去28日选择权重，但按价格MAE而非调度费用；用于判断费用反馈是否提供独立价值。
- `oracle_alpha_daily`：看到当天结果后从五个权重中选最低费用，只作为组合族的信息上界。

不再测试库存价值控制。它已在真实价格和oracle价格下触发科学失败证据。

## 3. Cheap PoC

### PoC Question

价格曲线收缩或只用历史已结算费用的在线选择，能否在不改变问题2 `combined` 供需与执行口径的条件下，同时改善验证期和评估期实际费用？

### Minimum Implementation

- 仍使用同星期负载预测、7日光伏均值、14日残差、0.8分位余量、1200kWh计划终端、原贪心因果执行器；
- 仍使用原六个14天窗口和共同窗口初始SOC；
- 每个候选的普通计划均在0点冻结，实际价格只用于对应时段结算；
- 滚动选择器的历史反事实只读取目标日前已经完成的日期；
- 保存逐日选择、候选历史得分、计划、逐时账本和独立审计。

### Selection Rule

Candidate A先在开发期从权重网格选出 `static_blend`。再在开发期比较 `static_blend` 与 `rolling_cost_selector`；库存调整费用相差不超过0.5%时按候选顺序选择更简单的 `static_blend`。验证期和评估期不重新选择模型或参数。

### Confounder Diagnostic

1. 扰动目标日及未来真实价格，所有可执行候选的0点计划和选择必须不变；
2. 逐日保存滚动费用得分，并独立从历史反事实重建所选权重；
3. 与 `rolling_mae_selector` 比较，检验直接费用反馈是否优于只追求价格误差；
4. 所有方法共用实际供需、实际结算价格、窗口初始SOC和库存调整口径；
5. `oracle_alpha_daily` 不参与选择，只报告该低维候选族的理论空间。

### Failure and Stop Conditions

任一未来信息泄漏、选择规则不可重建、能量/费用/SOC/功率误差超过1e-6或求解失败，判定算法失败。开发期选中方案若没有在validation和evaluation分别同时比 `mean7` 与 `fixed` 至少降低0.1%的库存调整费用，或不能优于 `rolling_mae_selector`，判定稳定费用目标失败。

完成本轮84天比较、独立审计和报告后停止。若失败，不能在相同窗口上继续扩大权重网格或调滚动天数；返回Workflow Recheck，寻找改变优化目标而非继续调价格点预测的新信息。若成功，仍须Human Model Gate批准后才能运行334天及生成 `result4-2.xlsx`。
