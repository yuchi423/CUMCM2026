# 问题4-2参考方法Detailed PoC协议

日期：2026-09-12。用户批准记录见 `memory/decisions/D-016-q4-reference-detailed-poc-approved.md`。本协议在看到新结果前冻结。

## PoC Question

上一轮价格预测收益不稳定，原因主要是价格点预测不足，还是实际执行器不根据当前及未来价格分配储能？参考用户提供文稿后，将两项机制拆开检验。

## Minimum Deliverable Question

能否在同一84天、同一供需与初始SOC上，分别给出当前模型、净负荷—价格预测、价格感知储能及二者组合的价格误差、实际费用、紧急购电、未用计划电、SOC和干预量，并通过独立物理、费用与信息边界审计？

## Scientific Validity Question

若费用下降，能否确认它来自因果可用的净负荷价格信息或正确对齐的储能价格信号，而不是修改普通购电计划、读取未来价格、更多消耗期末库存或供需口径变化？

## Minimum Implementation

所有方法继续使用问题2 `combined`：同星期负荷预测、7日光伏均值、14天残差、0.8分位余量、相同储能边界和5倍紧急购电。普通购电计划每天0点锁定。

比较以下四个候选：

1. `mean7_greedy`：上一轮7日同刻价格＋当前贪心执行器；
2. `netload_shape_greedy`：过去35日归一化价格形状×由当时可得净负荷预测回归出的日均价格，执行器不变；
3. `mean7_value_update`：7日同刻价格；在0、6、12、18点重算剩余时段的储能价值路径，普通购电量固定；
4. `netload_shape_value_update`：净负荷—形状价格预测＋价格感知储能更新。

控制与上界包括：附件1固定价＋贪心、价格感知储能所用价格错移6小时负对照、oracle＋贪心、oracle＋价格感知储能。

净负荷价格回归只用此前35个结束日。每个历史日的净负荷输入也按该日当时可获得的历史数据重建，不使用实际全天净负荷。6、12、18点只用已经实现的价格残差，以截断到[0,0.99]的AR(1)系数衰减修正剩余价格。

价格感知储能LP固定0点普通购电量，按预测供需缺口将有限电量优先分配给预计紧急购电价格更高的时段。日末只要求不低于1200kWh，并用当日凌晨预测均价乘放电效率作为透明的终端库存系数；库存价值只影响决策，不计作实际收入。实际执行继续光伏优先，已执行时段冻结。

## Performance Metrics

- 日前价格MAE、RMSE、日内Spearman相关；
- 实际普通购电费、紧急购电费、总费用、库存调整费用；
- 紧急购电量、已付未用电量、主动保留电池而发生的紧急购电量；
- 窗口首末SOC、储能LP求解失败、能量/费用审计误差。

开发期按库存调整费用选择四个候选。与最低值相差不超过0.5%时，按候选列表顺序选择更简单方案。Validation和evaluation不重新选择。

## Confounder Diagnostic

1. 扰动当天及未来真实价格，0点因果预测不变；6、12、18点预测只允许受扰动时刻之前的已实现价格影响。
2. 所有方法的普通计划在0点后保持不变；价格感知方法只能改变放电保留决策。
3. 价格感知方法与6小时错位负对照比较，检验收益是否来自正确的日内价格位置。
4. 报告现金费用与统一库存调整费用，禁止把终端库存价值计作实际收入。
5. 净负荷价格回归和价格感知储能分别单独运行，避免把组合改善全部归因于其中一项。

## Failure Conditions

任一未来信息泄漏、普通计划在日内改变、求解失败、费用/能量/SOC/功率误差超过1e-6，判定算法失败。开发期选中方案若未在validation和evaluation分别至少比 `mean7_greedy` 与 `fixed_greedy` 降低0.1%的库存调整费用，或不能优于错位储能负对照，则不支持稳定改进。若价格感知模型产生的优势只来自更低期末SOC，同样判定失败。

## Fallback and Stop Condition

失败时维持D-015批准的 `lag1` 操作性回退与附件1最终回退，不再叠加联合情景复杂度。完成8方法×84天、独立审计、三张图和报告后停止，不生成334天正式结果或 `result4-2.xlsx`，返回Human Model Gate。
