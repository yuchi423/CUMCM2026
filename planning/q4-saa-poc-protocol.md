# 问题4-2两阶段样本平均近似 Cheap PoC 协议

日期：2026-09-12。依据D-017的继续修改授权以及上一轮Workflow Recheck，本协议在看到结果前冻结。D-015双层目标、信息边界和回退不变。

## 1. 模型结构

每天0点的普通购电量 \(g_t\) 为所有情景共享的第一阶段变量。此前14个已结束日构成样本情景；每个情景包含由当天供需预测叠加历史预测残差得到的负载和光伏，以及可选的历史价格残差。情景内充放电、弃电、紧急购电和储电量为第二阶段追索变量。

目标函数为情景平均的普通购电费用、5倍紧急购电费用与统一期末库存价值：

\[
\min_g\;\frac1S\sum_{s=1}^{S}\left[
\sum_t p_{s,t}g_t+5\sum_t p_{s,t}b_{s,t}
-0.9\bar p_s E_{s,144}\right].
\]

同时加入一个不计入随机目标的名义情景：负载使用 `combined` 的同星期预测加0.8分位余量，光伏使用7日均值，禁止紧急购电且日末储电量固定为1200kWh。由此保留问题2已经确认的供需与余量要求。每时段普通购电上界为名义负载加最大充电量，避免通过无限购电再弃用形成非物理解。名义情景增加每时段一个0--1充放电状态变量，保证名义可行解不同时充放电；历史情景补救层保留连续变量并用极小循环成本打破退化。因此实现形式是“共享首阶段的SAA-MILP”，而不是声称纯LP已经显式保证互斥。

第二阶段允许在情景实现后调整储能和紧急购电，是标准两阶段近似。正式论文只能把它解释为“基于历史场景的日前鲁棒计划”；不能声称情景内决策精确复现逐时信息到达。最终仍用原贪心因果执行器在真实轨迹上评价第一阶段计划。

## 2. 候选与对照

- Candidate A `saa_load`：14个供需残差情景，全部用目标日14日均值价格；
- Candidate B `saa_joint`：同一历史日的供需和价格残差匹配；
- Negative control `saa_shuffled`：价格残差相对供需残差循环错开7日；
- Baselines：`fixed`、`mean7`、`mean14`；
- `oracle_actual`：使用当天真实供需和价格直接规划，只作非因果下界。

开发期比较 `saa_load` 与 `saa_joint`；相差不超过0.5%时选择更简单的 `saa_load`。验证期和评估期冻结模型。

## 3. 诊断与裁决

Confounder Diagnostic：

1. 目标日及未来真实价格扰动不得改变三个可执行SAA方案；
2. 联合SAA必须与保持边际分布但破坏日期匹配的 `saa_shuffled` 比较；
3. 报告计划购电量、已付未用电、紧急购电、期末库存和相对三种基线的费用变化；
4. 独立重建名义约束、全部情景目标、实际执行物理和费用；
5. 检查情景解同时充放电、第一阶段购电上界和求解状态。

Algorithm Failure Condition：未来信息泄漏、名义情景无法满足、任何约束/费用复算误差超过1e-6、第二阶段同时充放电或求解失败。

Scientific Target Failure Condition：开发期选中方案未能在validation和evaluation分别同时比 `mean7` 与 `fixed` 至少降低0.1%的库存调整费用；若选中 `saa_joint`，还必须在两个阶段都优于 `saa_shuffled`。

完成7方法×84天、独立审计和报告后停止。成功则返回Human Model Gate申请334天正式运行；失败则不继续增加情景数或调整库存价值，执行D-015操作性回退，并明确说明在当前不可预知电价口径与现有一年数据下，没有证据支持复杂价格模型稳定省费。
